说明：

- **匹配分**是**唯一的底层分数**（0-100）：四维平滑加权——经验匹配度 + 学历 + 履历稳定性 + 置信度，**近一年稳定销售额外 +12**，再减降权/P1/P2 软扣分。由脚本算好，**不要自己改算**。
- **推荐等级**（3 档固定分带）由匹配分推导：
  - `🟢 强推荐` = 匹配分 ≥ 60（`--pass-threshold` 或 `HR_PASS_THRESHOLD` 可调）
  - `🟡 待审核` = 40 ≤ 匹配分 < 60（`--review-threshold` 或 `HR_REVIEW_THRESHOLD` 可调下限）
  - `🔴 淘汰` = 匹配分 < 40
- **锁定待审核（硬规则）**：命中即把等级锁到 `🟡 待审核`（无论匹配分本来是强推荐还是淘汰），并在**简要分析**里以 `**【锁定待审核】…**` 粗体写出原因——① 有销售经验但最高学历为高中（含中专）；② 应届生且具备语言优势（小语种专业/较好语言水平）。如上表王海涛（88 分仍待审核）、林悦。
- **⚠️ 徽标**：候选人存在 P0 数据红旗（时间倒置、同期多份全职等）时，在推荐等级后追加 `⚠️`，并在**简要分析**里用粗体写出具体 P0。⚠️ **只提示、不改变分档**——是否录用由 HR 结合红旗判断。
- **排序**：先按推荐等级（强推荐→待审核→淘汰）分组，组内按匹配分从高到低；前三名用 🥇🥈🥉。（加了锁定规则后等级不再与分数严格单调，故按等级分组更贴合三档处理动线。）
- **简要分析**（最后一列）：一句话说清候选人的岗位背景 + 相关经验年限 + 学历 + 最匹配点/首要风险（+ P0 粗体）。这就是给 HR 的分析结论——**不要在表格外再单独列一段「简要分析/简要说明」，分析写在这一列即可**。需要更细的解析置信度/命中关键词/不匹配项/人工复核原因，用 `--output result.csv` 导出查看。
